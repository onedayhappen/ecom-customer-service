# 淘宝 ECD 多轮意图标注数据整理

本目录用于“根据多轮上下文识别最后一条用户输入的业务意图”。数据来自作者公开的完整 E-commerce Dialogue Corpus 压缩包，保留原话，不生成种子对话，不添加意图标签。

当前保留 **332,813 个多轮对话窗口**，每个窗口对应一个待标注目标。窗口不是独立完整会话：上游没有提供原始会话 ID，多个窗口可能来自同一会话。数据尚不能直接用于意图分类微调。

## 实际数量

| 原分集 | 原始匹配样本 | 正匹配样本 | 负匹配样本 | 最终多轮窗口/待标注目标 |
| --- | ---: | ---: | ---: | ---: |
| train | 1,000,000 | 500,000 | 500,000 | 327,968 |
| dev | 10,000 | 5,000 | 5,000 | 4,018 |
| test | 10,000 | 1,000 | 9,000 | 827 |
| 合计 | 1,020,000 | 506,000 | 514,000 | 332,813 |

原始行结构为 `0或1<TAB>上下文发言…<TAB>候选回复`。`1` 表示候选回复与上下文正匹配，`0` 表示负匹配，不是用户意图标签。

负匹配行不进入输出。正匹配行按以下互斥原因排除：

| 原因 | train | dev | test |
| --- | ---: | ---: | ---: |
| 只有一条上下文发言，非多轮 | 91,097 | 927 | 172 |
| 分集内上下文重复 | 63,847 | 8 | 1 |
| 与更高优先级分集的上下文完全重复 | 1,398 | 0 | 0 |
| 与更高优先级分集存在完整上下文的前缀包含关系 | 15,690 | 47 | 0 |

去重按 `test → dev → train` 的优先级进行，同分集保留最早来源行。仅删除窗口，不把测试数据移入训练集。重复判断忽略空白，但保存文本保持原样。

## 文件

- `train_dialogues.jsonl`、`dev_dialogues.jsonl`、`test_dialogues.jsonl`：多轮上下文窗口，每行包含原文 `messages`、来源分集、压缩包成员路径、原始行号、上下文指纹及角色推定状态。原始正匹配回复存于 `reference_response_excluded_from_input`，仅用于来源审计。
- `train_candidates.jsonl`、`dev_candidates.jsonl`、`test_candidates.jsonl`：待标注索引，通过 `dialogue_id` 对应窗口。`target_message_index` 指向该窗口最后一条用户输入，每个窗口只有一个目标。保留单订单/商品范围和角色待核验标记，不填入伪造的意图。
- `*_annotation_preview.jsonl`：每个分集前 20 个待标注输入，可直接查看；只包含截至目标用户消息的对话，不包含后续客服回复。样例是原始数据提取结果，不是合成种子。
- `excluded_positive_windows.jsonl`：被排除的正匹配窗口来源位置、原因、相关窗口 ID，不复制全部文本。负匹配行数量计入报告，原文仍保留在源压缩包中。
- `extraction_report.json`：源压缩包和各原始文件 SHA-256、输入/输出计数、输出文件 SHA-256、过滤规则和限制。

原始压缩包位于 `data/source_cache/ecd/E-commerce dataset.zip`，54,000,633 字节。SHA-256：

```text
41f09f0312b7611863794fb46d9f7f4061d8171901232ac3c17929295e4878b2
```

原始语料、对话、预览和候选索引被 Git 忽略；提取脚本、说明与不含对话原文的统计报告可跟踪。

## 角色和标注边界

1. **角色是推定的，不是显式标注。** 原文件没有 speaker 字段。按上下文从用户开始、用户与客服交替、最后一条为用户的结构整理，所有保留窗口均有至少 3 条、奇数条发言。奇数长度不能证明角色一定正确，训练前需要检查角色与实际内容是否一致。
2. **不能读取未来回复判断当前意图。** 标注输入只使用 `messages`；`reference_response_excluded_from_input` 不能展示给标注模型、分类器或人工标注员。脚本的 `materialize_prefix` 和预览文件已实施此隔离。
3. **不能直接视为 31 类训练数据。** 尚未标注意图，也没有承诺覆盖全部业务类别。每个目标需检查当前用户讨论的订单/商品是否单一、上下文是否足以判断。无法判定与业务上的 `others` 不是一回事。
4. **独立性仍需检查。** 已去除跨分集完全重复以及完整上下文互为前缀的窗口；没有原始 Session ID，无法证明所有集合在真实会话层面互斥。共享部分历史、裁剪得到的后缀窗口和语义近似重复仍需在正式训练前进一步分组审查。
5. **不将回复匹配标签用于意图分类。** 负匹配只说明候选回复不正确，不能将其标为 `others`；正匹配也不能直接映射到任何业务意图。
6. **保持原始文本。** 保留原分词空格、占位内容和用语，不改写、不补充客服回答，也不截断长上下文。实际文件存在单轮和超过 README 统计范围的长窗口，报告记录的是本次逐行统计结果。

## 复现和验证

在项目根目录运行，使用 Python 3.11 或更新版本的标准库即可：

```powershell
python scripts/extract_ecd_dialogues.py --download
python scripts/extract_ecd_dialogues.py --check
python -m unittest discover -s tests -p test_extract_ecd_dialogues.py
```

`--download` 获取作者完整压缩包（已有缓存时复用）并整理。已有缓存可直接运行脚本重新生成。`--check` 从源压缩包重新计算全部产物并核对散列，不写文件，也不需要网络。

测试覆盖负例和单轮排除、源文本保留、双向跨集合前缀包含过滤、完全重复过滤、最后用户目标、未来回复隔离、只读复现及产物被改动后的检出。
