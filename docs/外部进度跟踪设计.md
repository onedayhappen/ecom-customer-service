# 外部进度跟踪设计

## 等待记录与完成条件

已确认的业务操作通过 `operation_id` 绑定；普通查询支持 `get_logistics`、`get_after_sale_status`、`get_refunds` 的新版 `data` 回执。服务端必须先把事项明确转为 `waiting_external` 并保存查询证据编号，维护进程才建立等待；查询成功本身不会自动创建跟踪。生产轮询器按同一用户重新读取真实业务数据，不需要为查询类等待伪造操作编号。后续实际业务办理仍受普通售后/首次开票及渠道接入边界约束（BIZ-01、BIZ-06）。

事项等待业务系统、物流或处理方结果时进入 `waiting_external`，保存对象、申请号或运单、来源、实际阶段、下次查询时间与完成条件，不占用 ReAct 执行和模型额度。

完成条件由用户目标及有效原话决定：

| 用户目标         | 结束依据                                       |
| ---------------- | ---------------------------------------------- |
| 只提交申请       | 已核实的成功提交回执                           |
| 跟进退款         | 对应资金处理证据，说明渠道状态与银行入账的区别 |
| 查询指定物流     | 对应运单的进度；单票不能代表其他包裹           |
| 换货、维修或开票 | 核实相应子流程与交付范围，能力不足转人工       |

用户道谢、长时间不回复、模型生成了答复都不是业务完成证据。后来的跟进要求优先于此前“只提交”的范围。

## 查询与应用流程

```mermaid
flowchart LR
    Bind[由真实回执绑定等待对象] --> Due[发现到期等待]
    Due --> Claim[校验控制与领取租约]
    Claim --> Query[事务外查询业务事实]
    Query --> Validate[核验对象、时间与来源]
    Validate --> Apply[去重更新进度与公开事件]
```

`ExternalProgress` 从真实操作或查询回执创建 `task_external_waits`。查询类绑定保存契约版本 `2`、原始证据编号、事项目标与范围、确切运单或售后编号及完成条件。首次绑定核验内部系统事件、工具参数、成功状态、MySQL 来源、60 秒内观察时间、事项版本链和控制版本。

`get_logistics` 固定到一票原发货、退货或补发包裹；多个候选或分页结果不能默认选择第一票。显式指定的原发货／补发运单具有有效签收时间时，可完成这一票的跟踪；订单概览和退货签收不自动代表整单履约、仓库验收或退款完成。签收争议保持等待并交人工。

`get_after_sale_status` 固定到其售后申请；`get_refunds` 根据对象引用和回执确定售后申请，多个未指定的申请不自动合并。商品行、SKU、数量、订单、平台和商家在发布前重新核对。退款完成需要完整未分页记录、申请金额与币种相符、渠道编号和有效完成时间；部分退款、缺凭据及通用“处理完成”状态不能作为全额退款证明。明确要求银行到账的目标，在渠道成功后转人工核实；普通渠道处理结果仅说明渠道成功与银行实际入账的区别。

每轮按数量上限领取到期记录；领取前检查新输入、归属澄清、事项版本、暂停和接管。查询在事务外执行，不调用模型、不准备或重试业务提交。

应用结果时再次核验租约、当前事项版本和控制状态。查询类等待在领取和发布前还复核原始事件是否被撤回、来源凭据是否有效、目标和对象是否改变。正常等待与进度更新可以沿版本链继续使用最初的绑定，后续轮询不要求最初查询始终小于 60 秒；目标、对象或控制权变化须重新核实。迟到查询不能覆盖已改变的目标或恢复已暂停的事项。

## 去重与事件顺序

`task_external_receipts` 按事项与稳定外部事件编号去重。记录业务来源时间与观察时间，重复结果不重复发布。

旧时间、更低阶段、来源切换或同一时间的冲突结果不直接覆盖进度，保留错误并重新核实。不能只用“后收到”判断业务更晚。

进度变更、事项版本、外部回执与公开通知在同一事务保存。已直接发布的外部进展不会再唤醒一次空的 Agent 执行，避免重复追问。

## 多商品与多包裹

售后申请、原发货、退货和补发包裹分别关联商品行和数量。只核实某个运单时，公开说明仅代表这一票。

退货仓库收货、商品验收、退款成功与换货补发签收是不同阶段。用户提出签收争议时同时保留系统状态与用户陈述，不以物流字段否定争议。

## 失败与恢复

等待安排、尝试次数、下次查询时间、租约及最近观察保存在数据库。进程退出后按到期安排继续，重复领取受租约约束。

退役 `query_*` 回执或没有新契约的旧查询等待不自动改名或重定向；发现或恢复时转人工核实，记录 `external_scope_unverified`，不会用旧数据推进事项。已确认操作的原有恢复路径保留。

超时、次数耗尽、期限已到、业务拒绝或来源无法核实时进入人工路径。等待和恢复只查询原对象，不重复提交申请，也不承诺尚未接入的离线推送。
