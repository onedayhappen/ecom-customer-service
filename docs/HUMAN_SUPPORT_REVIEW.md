# 人工接管与工单：实现后 Review

分支：`codex/require-human`。本记录为实现后的代码自审与本地验证，不代表生产容量认证。

## 已修复的问题

| 检查点 | 风险与修复 |
| --- | --- |
| 人机并发 | 接管后旧 LLM、旧确认令牌和旧排队任务可能继续生效；增加会话控制版本，在工具写入和公开消息发布事务中再次检查 |
| 同请求重复执行 | 同步路径的同 ID 并发请求原本可能重复进入 Agent；增加数据库执行占位与结果回放，不重跑结果未知的任务 |
| 入队失败与重试 | 重试失败可能错误释放原任务占位；单独实现入队占位释放，并绑定确认参数指纹 |
| 业务调用进行中接管 | 不能撤回已经提交到下游的退款；持久化 running/unknown 状态，阻止恢复与重试，提供管理员核实流程及迟到结果审计 |
| 工单授权 | 抢单、转派、停用、私有备注、历史工单均在服务端校验；恢复机器人后原工单按结束序号截断，防止后续消息泄漏 |
| 历史消息 | 模型上下文窗口不能替代完整历史接口；完整公开历史与最近 40 条模型上下文分别读取 |
| 数据库提交 | PostgreSQL 连接池吞掉提交异常、MySQL DAO 归还连接前未提交；修复并添加失败边界测试 |
| 浏览器通信 | 原 CSP 写死 8000 端口；按 API 配置生成 CSP。CORS 包裹认证中间件，401/403 可读，并允许 SSE 续传请求头 |

## 验证

- 后端回归：390 项通过，2 项现有 Redis 集成测试显式排除。新增接管/工单测试 36 项，覆盖并发抢单、公开/内部消息隔离、幂等冲突、身份越权、转派停用、历史边界、接管期间写操作、未知结果核实、过期 AI 结果和确认令牌失效。
- 现有 Redis 测试固定连接本机 6399/15 且调用 `FLUSHDB`，其中一个在提交任务之后清空数据库；本次没有对该数据库执行这些测试，也没有把它们计为通过。
- 前端 `npm run build` 通过，包含默认 API 地址及同域相对地址 `/` 的构建检查。
- 使用 Edge / Playwright 两个独立浏览器上下文验证登录、转人工、领取、公开回复、内部备注、恢复机器人、历史工单回看与后续消息隔离；无 JavaScript 运行异常。检查了桌面及 390px 手机视口，未出现水平溢出。
- 浏览器测试使用独立 SQLite 文件、测试身份和模拟机器人回复；人工收发、权限、SSE、工单 API 使用实际代码，没有调用真实 LLM、订单系统或用户数据库。
- `git diff --check` 通过。保留原工作区已有的 `README.md` 与 `docs/BUSINESS_SCENARIOS_REVIEW.md` 改动；本次未提交、推送或部署。

新增后端测试可用 `python -m pytest -q tests/test_human_support.py tests/test_human_support_api.py` 单独运行，测试会配置临时 SQLite 存储。

全量回归时使用隔离配置：订单数据库与各 Redis URL 置空，会话/记忆后端使用 JSON，关闭真实意图模型与审计数据库，启用日志观测，聊天使用 sync。Windows 下请从真实 Python 文件或 `python -m pytest` 启动，避免原有 multiprocessing 测试从标准输入脚本启动失败。
