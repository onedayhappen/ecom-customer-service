# 05 修正错误关联并阻止错误继续传播

发现消息接错事项后，只修正受影响内容，保留正确进度，并阻止旧结果继续使用。

前置：完成 [04 判断消息归属并处理不明确的回答](04-message-association.md)。 总体约束见 [完整方案](../AGENT_REFACTOR_PLAN.md)。

## 改动位置

`app/tasks/service.py`、`app/reliability/mutations.py`、`app/session/short_term.py`、`app/memory`、`app/support/store.py`。

## 实施步骤

1. 将用户明确纠正、工具发现对象冲突、服务端校验失败作为纠错入口。记录原消息、原决定、受影响事项和原因；再次纠错也用事件追加保存。
2. 先让受影响执行、待确认操作和未发布回复失效。统一提供版本检查与失效通知接口，供 06、08、09 接入，不能只改展示文字。
3. 按变更来源定位错误字段，检查它们之后是否又被修改。仅恢复或修正错误造成的部分，存在冲突时重新合并或澄清，不恢复整个事项旧快照。
4. 将消息重新关联到明确的正确事项；不明确则进入待澄清。错误新建且没有业务操作的空事项可以结束并保留修正记录，不能删除原话与历史回执。
5. 记录受影响来源已失效，读取摘要、缓存和记忆时立即排除相关结论，再异步重建。10 的记忆维护和 11 的检索缓存必须复用该规则，重建期间不能继续返回旧内容。
6. 对已发布的错误回复补发简短更正。若业务已开始、已成功或结果未知，保留操作记录并查询真实状态；自动办理暂停，按已有业务规则补救或交人工。

## 验收

- 把 A 的原因错记到 B 后纠正，只修改相关字段，其他补充保留。
- 错误之后已有新的正确修改，纠错不会用旧值覆盖它。
- 旧确认和未发布回复被阻止；重建前后的摘要和缓存都不会重新提供错误结论。
- 重复纠错不重复撤回；存在已成功或未知操作时不宣称业务已撤销。

## 本次交付边界

交付可重复执行的纠错服务、失效检查和补救分支。通过模拟回执覆盖已经办理的情况，不实际触发退款。
