# 前端交互设计

## 界面与模块

前端使用 React、Vite 和普通 CSS。客户工作台提供聊天、订单、优惠券和个人资料；人工工作台提供工单、公开回复、内部备注、客服授权与未知操作核实。

| 模块                               | 职责                                   |
| ---------------------------------- | -------------------------------------- |
| `App.jsx` / `auth`                 | 登录状态、注册登录及客户或客服入口     |
| `CustomerWorkspace.jsx`            | 客户导航，切换页面时保留聊天挂载与草稿 |
| `commerce` / `CustomerProfile.jsx` | 业务列表、筛选、分页及会员资料         |
| `TaskConversation.jsx` / `chat`    | 对话组装、订阅、发送与超时反馈         |
| `chat/Attachments.jsx`             | 鉴权图片预览、识别状态轮询、撤回和重试 |
| `OperationConfirmation.jsx`        | 具体操作内容、确认、取消和结果刷新     |
| `InvoiceDocuments.jsx`             | 开票申请进度、票据来源和授权文件下载   |
| `SupportConsole.jsx` / `support`   | 工单列表、处理、权限及人工核实         |
| `api/client.js`                    | Cookie、CSRF、取消和错误处理           |
| `conversationState.js`             | 消息合并、游标、重试及回复覆盖判断     |
| `styles`                           | 基础、认证、客户与人工界面样式         |

## 会话加载与事件恢复

打开会话先读取历史快照及一致事件游标，再建立 SSE。消息按会话序号和稳定编号合并，游标只向前移动。

切换会话或卸载时取消读取，迟到响应不能写入其他会话或清空新草稿。切换客户导航不等于创建新会话。权限撤回后停止订阅并清理受保护内容。

查看更早消息独立分页，分页失败保留已经加载的内容。服务端时区信息保留；缺少时区后缀的日期按 UTC 解释，再按浏览器本地时区展示。

## 持续输入与重试

发送期间允许继续输入，每条消息有独立 `request_id`。HTTP 超时不代表未接收，重试使用原编号；SSE 或历史已证明接收时移除待重试状态。

HTTP 回执、SSE 与业务回复的顺序不固定。输入提示按回复覆盖的 `received_sequence` 判断，较早回复不能清除较新问题的等待状态。

前端超时提示用于显示等待情况，不写入会话、不取消后台事项或业务操作。迟到真实回复仍正常合并。

Enter 发送、Shift+Enter 换行；输入法候选确认和长按重复按键不会重复发送。

图片先逐张上传，再把附件 ID 按顺序随消息发送，允许纯图片消息。上传中阻止发送未完成附件；已接收消息识别失败时，重试创建引用原消息的新补充输入，不重发整段原文。当前附件组件每 5 秒轮询元数据直到识别终态，尚未使用图片识别完成事件驱动刷新；SSE 目标与当前差异见 [待改进](待改进.md) 的 `IMG-09`。

## 确认卡片

卡片展示服务端固定的对象、商品、数量、金额性质、影响与有效状态。确认提交使用原操作编号、凭证和当前会话，不允许浏览器替换办理参数。

同一操作不并发提交。确认中取得的状态不能被较旧轮询快照覆盖；刷新页面恢复同一操作。结果未知时刷新原结果，不创建新的办理请求。

卡片失效后继续对话重新核实，不能仅在浏览器启用旧按钮恢复授权。

操作结果包含开票申请编号时，[InvoiceDocuments](../frontend/src/InvoiceDocuments.jsx) 独立查询申请进度，每 5 秒刷新，终态停止；卸载时取消请求，查询失败显示错误并自动重试。文件可用后展示鉴权下载入口，避免将“申请提交成功”显示为“文件已生成”。确认卡片、票据和人工交接保留演示标识，模拟退款及演示票据不显示为真实到账或正式开票。

## 人工工作台与数据界面

`TaskHandover.jsx` 展示服务端投影的交接事实：候选对象、历史查询、准备操作和业务回执分别标识，保留范围、时间、缺项、截断与图片不确定性。没有载入摘要的字段显示为待核对，不在浏览器从空值推断“没有订单/退款”。工单释放后仍遵守后端冻结的历史范围。

客户与客服消息保留说话人和来源，内部备注仅在授权工作台展示。工单历史边界由后端检查，界面不通过隐藏控件代替权限控制。

订单与优惠券列表的筛选、游标和加载状态属于对应页面；迟到分页不混入其他筛选结果。金额与日期使用共享格式化，未知值明确展示，不在客户端推断支付或资格。
