# 运行与可观测性设计

## 进程职责

| 进程         | 边界                                                     |
| ------------ | -------------------------------------------------------- |
| API          | 接收、认证、状态查询、确认及 SSE；不持有事项唯一执行权   |
| 事项 Worker  | 改写、关联、调度、ReAct 与回复组织；内置独立图片队列处理 |
| 记忆 Worker  | 提取、更新、遗忘、归档截止点                             |
| 通知 Worker  | 发布持久化会话事件的变更通知                             |
| 维护进程     | 恢复、清理、归档与外部等待查询                           |
| 交易 Worker  | 本地待付款超时及处理方请求、回执                         |
| 可选检索服务 | 独立执行带服务认证及额度控制的政策检索                   |

进程通过共享数据库、Redis 与一致配置协调。Python 线程池用于有上限的网络并发，不能替代跨进程唯一性、租约和业务锁。启动、测试、构建与运维命令集中在 [项目 README](../README.md)。

图片 `ImageWorker` 在 `ConversationWorker` 中构造，负责首次识别和定期文件清理；它不是单独的命令行进程。短期摘要由维护进程推进；独立记忆 Worker 调用 v3 处理，维护进程仍有记忆兼容处理入口，以数据库租约协调。配置、挂载与制品边界见 [配置与部署设计](配置与部署设计.md)。

## 可靠调度与通知

任务状态与必要唤醒记录先持久化，再通知 Redis。领取者凭数据库状态和租约获得执行权，Redis 消息丢失或重复不会改变原始事项事实。

通知 Outbox 与公开事件共用事务。Pub/Sub 只表示会话发生变化，实际内容按数据库游标读取；定时补拉覆盖丢失通知，重复通知由稳定事件编号去重。

模型或工具调用在事务外完成，返回时复核控制与来源。过期执行者不得通过迟到响应覆盖新版本。进程重启恢复未开始或允许重新核实的工作，未知业务写入只查询原回执。

## 额度与资源预算

| 维度             | 约束                                         |
| ---------------- | -------------------------------------------- |
| 入站请求         | 用户、租户与全局额度；读、聊天和控制分别计数 |
| 事项执行         | 全局、租户和用户并发，等待不占运行槽位       |
| 模型             | 模型并发、调用频率和输入输出 Token 预留      |
| Embedding 与检索 | 独立额度，避免索引任务挤占聊天容量           |
| SSE              | 用户共享连接数、进程上限与连接租约           |
| PostgreSQL       | 每进程、每 DSN 的连接池容量和等待超时        |

Token 预留是应用估算，不等于供应商精确计费。扩容增加各进程连接池及本地应急额度，不能只提高副本数而忽略数据库与模型总容量。

Redis 故障时，部分入口可以使用有上限的进程级应急限制，执行资源的共享额度仍按失败策略处理。数据库不可用时不能返回虚假的接收成功。

## 自动处理控制

装配开关控制接口和能力是否启用，数据库中的放量模式控制哪些用户允许自动处理：

- `stopped`：停止自动处理。
- `selected`：按用户启用。
- `all`：整体启用，保留显式用户限制。

控制变化增加版本，使旧执行、未使用确认和旧结果失效。暂停仍允许保存消息、读取历史和人工处理；它不能撤销已经发出的外部业务请求。

恢复先核实执行中与未知操作，再按当前事项和新控制版本调度，不重放业务写入。备份恢复也不能撤销外部支付或售后系统的真实效果。

## 交互日志

`interaction_trace_events` 保存阶段记录，`interaction_trace_sessions` 保存导出状态。每个会话导出一个 `logs/traces/conversations/session-<session_id>.jsonl` 文件，每行对应以正式客服回复为边界的一轮交互。

一轮可以包含多条用户消息、多个批次和多个事项；模型调用或进度提示不单独划分交互。阶段数据可重建日志文件，文件丢失不改变事项或业务状态。

| 字段                            | 含义                                         |
| ------------------------------- | -------------------------------------------- |
| `interaction_id` / `session_id` | 交互和会话标识                               |
| `user_messages`                 | 本轮原话、消息序号和请求编号                 |
| `assistant_reply`               | 实际发布的答复；未回复时为空                 |
| `status`                        | 已回复、处理中、失败或长时间无后续进展       |
| `steps` / `errors`              | 改写、关联、执行、证据、确认、发布和错误记录 |

日志不记录隐藏推理或可重放的确认凭证，敏感业务字段按数据范围与脱敏规则处理。追踪 ID 用于串联实际事件，不构成新的业务授权。

## 指标与状态恢复

API、Worker、通知进程各自提供指标。进程级连接数与连接池指标按实例统计；数据库全局队列 Gauge 不能跨副本求和重复计数。

重点观察排队年龄、任务状态、数据库连接等待、模型与工具失败、通知积压、未知操作及控制模式。归档移出终态执行的大 payload，保留必要状态、幂等占位和回执；归档不等于立即释放数据库磁盘。

本地向量索引与模型文件通过版本化快照部署，不把本地目录视为分布式存储。Nginx 对 SSE 禁用代理缓冲，客户端断线后用游标恢复。
