# 政策检索设计

## 检索职责

政策 RAG 返回当前咨询真正适用的条款，而不只选取语义相似文本。业务工具 `search_policies` 返回完整条款、来源、版本、时间区间与缺失条件，Agent 结合已经核实的业务事实解释。

政策不能替代订单状态、金额、库存、会员资格或实际办理回执，也不能通过自然语言授予退款或改价权限。

## 知识单元与元数据

知识文本位于 `app/rag/knowledge`，按完整条款或小节组织。对应 `名称.policy.json` 保存审核状态、来源、版本、访问范围、平台或店铺、渠道、品类、生效与失效时间。

元数据缺失不由模型补造。生效区间为包含起点、不含终点；历史咨询选择适用版本依赖规则声明的时间依据，不能一律使用当前最新版或购买时版本。

向量模型标识与索引版本绑定，更换模型时需要配套重建。目录中存在 Markdown 不代表已有审核资料或可用索引。

### 审核与切分

正文、元数据与源码依据的摘要保存在 [审核记录](knowledge_review.json)，用于检查服务说明与项目实现的一致性。正文维护和审核记录格式见 [知识库审查与维护](知识库审查与维护.md)；运行时以当前发布指针和索引校验结果为准。

当前存在两种切分入口：普通 `chunk_markdown_file` 按二级标题切分，超长章节按段落拆分，阈值为 1200 字符；正式 `policy_chunks` 要求侧文件，将文首限定语附在各章节上，保留完整章节，超过 12000 字符直接拒绝并要求编辑拆分。不能把普通切分与正式政策发布的行为混为一谈。

### 侧文件填写契约

侧文件与正文同名，例如 `return_process.md` 对应 `return_process.policy.json`。字段以 `PolicyMetadata` 为准，未知字段会拒绝；不能使用已删除的旧 YAML 中 `title/category/id` 替代完整审核信息。

| 字段 | 必须核实的内容 |
|---|---|
| `source_id`、`version` | 可追溯来源编号及版本；同一发布中来源/版本组合不能重复。 |
| `source_uri` | 真实、无凭据 HTTP(S) 来源地址，或 `repo:app/rag/knowledge/<文件名>.md`。仓库来源仅接受规定目录下的简单文件名，必须与对应正文匹配，不执行文件读取或网络请求。自编说明不能冒用电商平台官网。 |
| `rule_key` | 所属规则标识，用于识别相互冲突的条款版本。 |
| `platform_code`、`store_id`、`channel`、`category` | 已核实适用范围；`*` 表示该维度普遍适用，不能因为不知道就填 `*`。 |
| `audience` | `public` 或 `staff`；面向用户的检索不会返回工作人员专用资料。 |
| `selection_basis` | `request_at`、`order_created_at` 或 `delivered_at`，需明确应按哪个业务时点选规则。 |
| `selection_reference` | 时间选择依据，说明如何确认上述口径。 |
| `effective_from`、`effective_until` | 带时区的生效起点和可选终点；终点须晚于起点，结束时刻不包含。 |
| `reviewed` | 仅允许 `true`，需先完成实际来源、范围、内容审核。不是为了通过校验而填写的默认值。 |

正文摘要 `source_digest` 在切分时计算，不应手工填入侧文件。本项目通用服务说明明确限定本项目能力，使用全范围 `*` 和 `request_at`；这不表示所有订单享有相同权益，也不替代业务规则。若增加具体平台、商家或历史权益条款，必须另行核实适用范围和时间依据；缺少资料时不发布。

## 检索流程

```mermaid
flowchart LR
    Scope[事项条件与有效业务回执] --> Filter[访问、店铺、渠道、品类与时间过滤]
    Filter --> Search[关键词检索 + Chroma 向量检索]
    Search --> Rank[合并排名与去重]
    Rank --> Evidence[完整条款、来源、版本和限制]
```

涉及订单的适用条件从已鉴权、属于该事项且仍有效的业务事实构造，不以用户陈述替代未知业务字段。多商品订单需要明确商品行或确认统一品类，不能任意选择其中一个品类。

先过滤不适用、未审核或已撤回来源，再检索正文。关键词与向量结果合并、去重后返回有限片段；无关最近邻、版本冲突和条件缺失都不能伪装成有效答案。

当前 `PolicyRetriever` 用词法排名和向量排名做 RRF 融合，常数为 60；按正文摘要去重，返回完整条款而不是任意截断句子。基础 `search_policy` 接口允许 1～5 条；业务工具 `search_policies` 固定请求 3 条，工具回执封装在 `data.policy_evidence` 并附 `rule_checks`，不能把两种接口结构混用。

当前业务工具通过已鉴权的 `subject_ref` 从 MySQL 构造适用上下文；有订单时读取其创建时间及实际包裹签收依据。通道等必要字段缺失时可能拒绝检索，而不是由模型补齐。`task_policy.py` 还保留基于事项工具证据的上下文构造入口，学习时应沿实际调用者区分。

## 回执与发布校验

回执包含条款正文、来源地址、文档与政策版本、适用范围、时间依据、正文校验值和索引版本。

后续模型、工具与回复发布阶段重新检查事项条件、订单依据和索引状态。来源撤回、索引切换、条件变化或证据过期后，不继续使用旧条款。

完整政策答复和证据保留用于用户查看及审计。后续历史上下文中的政策正文使用需要重新检索的提示，不能把曾经适用的条款当作永久授权。

## 发布、回退与远程检索

`PolicyIndex` 使用版本化索引发布和切换，不在正在使用的集合中直接全量删除重建。发布需要审核元数据及可用 Embedding；回退也检查模型标识和发布版本。来源可以按编号及版本撤回。

发布清单、当前版本指针与撤回记录保存在 Chroma 目录旁的 `<collection>.policy-releases.sqlite3`；向量存在对应不可变 Chroma collection 中。这份 SQLite 是本地索引控制数据，不是订单或客服运行库，备份与分发索引时需一并处理。

本地检索使用 Chroma。可选远程检索服务通过固定服务地址与令牌接入，对查询、结果数量、结构和响应大小设限。检索服务本身不递归调用远程检索。

嵌入式 Chroma 目录不是跨主机共享数据库。多个检索副本使用相同版本的索引快照与模型标识。

### 发布与核验步骤

先确认逐篇侧文件及实际来源，再在相应部署环境运行。以下命令不能弥补元数据缺失：

```powershell
# 预检完整知识目录，缺失元数据或超长章节会失败
python -c "from pathlib import Path; from app.rag.chunker import policy_chunks; print(len(policy_chunks(Path('app/rag/knowledge'))))"

# 构建完整版本并切换指针，记录输出中的 generation 等发布标识
python -m app.rag.commands.policy_index publish

# 检查磁盘正文/元数据、当前发布及实际索引内容一致
python -m app.rag.commands.policy_index verify

# 检查技术审核摘要和配置主题的真实模型检索
python -m scripts.verify_policy_knowledge

# 必要时将占位符替换为已核实的历史版本或来源编号
python -m app.rag.commands.policy_index rollback <generation>
python -m app.rag.commands.policy_index revoke <source_id> --version <version>
```

尖括号是说明占位符，执行前必须替换。自定义 `--kb-dir`、`--persist-dir` 和 `--collection` 参数放在 `publish/rollback/revoke` 子命令之前。

发布后用实际鉴权事项及属于本人的订单/商品执行 `search_policies`，检查条款、来源、有效期、索引标识和 `rule_checks`。测试无关问题不返回近邻假依据，范围缺失或版本冲突会明确拒绝；来源撤回或版本切换后旧证据失效。`business_policy_versions.rules` 的 `rag_policy_id` 和 `rag_policy_version` 未关联时，检索文本不能声称与可执行规则版本已经一致。

`python -m app.rag.commands.update_index` 只同步普通 `ecom_kb` 及内容哈希清单，供旧检索路径使用，不创建 `PolicyIndex` 发布版本。该命令成功不代表当前政策工具可用。Docker 使用独立挂载目录，需在对应容器环境发布和验证。

## 失败边界

模型、索引、适用条件或可靠条款不可用时返回明确缺项，转入补问或人工处理。不用过期缓存或模型常识伪造政策依据。条款、附件和工具返回是资料，不能修改系统指令、权限或确认要求。

政策文本与用户记忆分别过滤：政策允许普通密码要求、防诈骗提示和来源标识，拒绝凭据赋值、密钥/令牌形态及指令注入；用户记忆的严格敏感词过滤保持不变。检索和回复证据重验都执行政策检查，不以 `reviewed=true` 跳过正文安全或版本校验。
