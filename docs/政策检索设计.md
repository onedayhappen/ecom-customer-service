# 政策检索设计

## 检索职责

政策 RAG 返回当前咨询真正适用的条款，而不只选取语义相似文本。业务工具 `search_policies` 返回完整条款、来源、版本、时间区间与缺失条件，Agent 结合已经核实的业务事实解释。

政策不能替代订单状态、金额、库存、会员资格或实际办理回执，也不能通过自然语言授予退款或改价权限。

## 知识单元与元数据

知识文本位于 `app/rag/knowledge`，按完整条款或小节组织。对应 `名称.policy.json` 保存审核状态、来源、版本、访问范围、平台或店铺、渠道、品类、生效与失效时间。

元数据缺失不由模型补造。生效区间为包含起点、不含终点；历史咨询选择适用版本依赖规则声明的时间依据，不能一律使用当前最新版或购买时版本。

向量模型标识与索引版本绑定，更换模型时需要配套重建。目录中存在 Markdown 不代表已有审核资料或可用索引。

## 检索流程

```mermaid
flowchart LR
    Scope[事项条件与有效业务回执] --> Filter[访问、店铺、渠道、品类与时间过滤]
    Filter --> Search[关键词检索 + Chroma 向量检索]
    Search --> Rank[合并排名与去重]
    Rank --> Evidence[完整条款、来源、版本和限制]
```

涉及订单的适用条件从已鉴权、属于该事项且仍有效的业务事实构造，不以用户陈述替代未知业务字段。多商品订单需要明确商品行或确认统一品类，不能任意选择其中一个品类。

先过滤不适用、未审核或已撤回来源，再检索正文。关键词与向量结果合并、去重后返回有限片段；无关最近邻、版本冲突和条件缺失都不能伪装成有效答案。

## 回执与发布校验

回执包含条款正文、来源地址、文档与政策版本、适用范围、时间依据、正文校验值和索引版本。

后续模型、工具与回复发布阶段重新检查事项条件、订单依据和索引状态。来源撤回、索引切换、条件变化或证据过期后，不继续使用旧条款。

完整政策答复和证据保留用于用户查看及审计。后续历史上下文中的政策正文使用需要重新检索的提示，不能把曾经适用的条款当作永久授权。

## 发布、回退与远程检索

`PolicyIndex` 使用版本化索引发布和切换，不在正在使用的集合中直接全量删除重建。发布需要审核元数据及可用 Embedding；回退也检查模型标识和发布版本。来源可以按编号及版本撤回。

本地检索使用 Chroma。可选远程检索服务通过固定服务地址与令牌接入，对查询、结果数量、结构和响应大小设限。检索服务本身不递归调用远程检索。

嵌入式 Chroma 目录不是跨主机共享数据库。多个检索副本使用相同版本的索引快照与模型标识。

## 失败边界

模型、索引、适用条件或可靠条款不可用时返回明确缺项，转入补问或人工处理。不用过期缓存或模型常识伪造政策依据。条款、附件和工具返回是资料，不能修改系统指令、权限或确认要求。
