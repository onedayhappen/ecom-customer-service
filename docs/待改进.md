- **实现：** [collection_queries.py](../app/services/commerce/collection_queries.py) 将订单、售后、持券及发票列表改为 SQL 筛选与键集分页；当前页购买摘要、售后行和发票文件批量读取。订单行的物流数量、售后占用和状态由数据库批量聚合。付款、退款及订单物流也使用 SQL 分页，订单／售后／包裹摘要不再读取完整订单行。已有商品搜索的 SQL 分页与规格聚合保留。

### IMG-01：共享存储适配、独立预览与临时地址（P2）

- **现状与依据：** [MediaService](../app/media/service.py) 直接操作本地 `Path`，每资产只写 `original` 和 `model.jpg`；[content API](../app/api/attachments.py) 的预览复用模型图。没有对象存储适配、独立预览缩放参数或签名 URL 发行服务；同机共享挂载已经可用。
- **验收：** 明确存储后端与变体契约，哈希/尺寸/处理版本可回查；多副本读取同一材料，临时地址过期不影响附件身份；鉴权覆盖所有变体。保留当前鉴权读取作为有效路径。

### IMG-02：引用感知的材料保留与清理（P1）

- **现状与依据：** [upload/cleanup](../app/media/service.py) 按上传时设置统一 `expires_at`，到期即撤回并删文件，没有因消息、事项或售后引用延长保留的策略。
- **验收：** 区分未发送临时附件与仍被有效材料关系使用的文件；在保留策略允许的范围内保护有效引用，并明确最终到期/用户撤回行为。若增加物理去重，还需关系计数和独立权限，不能按单个引用删除共享字节。

### IMG-03：初次识别尚未包含必要历史与图片位置（P2）

- **现状与依据：** [bind_message](../app/media/jobs.py) 保存当前消息文字和单图；重试附指定原消息。没有加载先前客服问题、选项或向视觉请求传入完整的消息内图片位置。
- **验收：** 以消息截止点固定必要公开前文和图片顺序，区分用户问题与图片事实；后来消息不改变在途快照。覆盖纯图回答“请拍标签”和“第二张”等指代。

### IMG-04：OCR、局部裁剪、多图比较和结构化候选（P3）

- **现状与依据：** [VisionClient.observe](../app/media/vision.py) 每次发送单张完整归一化图；`visible_text` 是字符串、`candidate_entities` 是字符串列表。没有专用 OCR/裁剪流程、联合多图请求或候选实体与字段位置的结构化映射。
- **验收：** 需要这些能力时扩展输入和观察契约，记录全部图像版本、裁剪来源及候选字段；联合结论不冒充某一张图片的独立事实。原有单图观察继续可读。

### IMG-05：按需识别没有在途请求合并（P2）

- **现状与依据：** [prepare/inspect/persist](../app/media/service.py) 先查成功观察缓存，唯一 `reuse_key` 防止重复结果落库；同时未命中缓存的请求仍可分别调用模型，没有进程内 single-flight 合并。
- **验收：** 相同有效输入共享在途只读识别，失败和取消不误缓存为成功，跨进程仍以租约/版本及唯一提交保证状态一致。模型恰好调用一次不作为可保证条件。

### IMG-06：目标状态机、替代关系与检索索引未齐（P2）

- **现状与依据：** [schema.py](../app/media/schema.py) 有状态文本列和 `supersedes_id`，但 [service.py](../app/media/service.py) 未实现资产 `preparing/failed` 及观察 `superseded` 流转，也没有填写观察替代关系；非唯一的观察检索、资产过期和事项附件检索索引未覆盖设计中的全部访问方式。
- **验收：** 明确当前与目标状态转换、重试和不可变结果规则，补齐真正使用的索引及版本迁移；只增加可为空的字段不算完成。

### IMG-07：图片任务完成未写可靠唤醒事件（P2）

- **验收：** 任务终态与通知意图原子提交，重复通知可去重，通知丢失可补拉。保持消息连续前缀、输入屏障和租约检查，不由图片 Worker 直接办理业务。

### IMG-08：图片上下文优先级与历史压缩不够细（P2）

- **现状与依据：** [task_images](../app/media/context.py) 最近优先、最多 32 条并受总预算限制，超限保留部分引用和遗漏数量；没有将当前追问图片单独置顶或完整的历史图片清单分页，普通引用摘要也不保证保留每项图片问题与未解决项。
- **验收：** 当前消息、追问对象及未解决材料优先；压缩后仍可定位更早附件，明确遗漏数量和范围；不可因最近图多就永久无法定位当前被问到的旧图。

### IMG-10：视觉共享额度与供应商用量未独立核算（P2）

- **现状与依据：** 上传字节、像素、每用户资产数和 [图片线程池](../app/media/jobs.py) 已有上限；[按需识别](../app/tasks/execution.py) 消耗事项模型次数。视觉 SDK 直接调用，没有复用文本 `model_budget` 的共享频率/Token 额度，也未持久化供应商图像用量；首次识别主要受任务和本地并发限制。
- **验收：** 多进程按用户/租户/全局约束视觉容量，首次和按需识别都计量实际调用，保留时间与供应商用量但不记录图片字节；不以文字 Token 估算代替图像成本。

### IMG-11：客服没有独立识别授权入口（P3）

- **现状与依据：** [attachments API](../app/api/attachments.py) 的 `ticket_id` 支持授权客服读取，但重试仍调用当前身份的 `MessageIntake.receive`；[前端](../frontend/src/chat/Attachments.jsx) 在工单视图隐藏重试。机器人被接管后不能借旧执行调用 `inspect_image`。
- **验收：** 若需人工触发识别，提供客服角色、工单历史边界、明确来源与独立预算的入口，不借用用户身份或恢复已失效机器人资格。

### IMG-12：图片专用运行指标尚未完整提供（P2）

- **现状与依据：** 图片元数据与队列保存状态和错误，通用 [指标](../app/observability/metrics.py) 及 [运行采集器](../app/runtime/metrics.py) 没有完整暴露文档列出的上传失败率、识别延迟、缓存命中、视觉用量与清理等专用指标。
- **验收：** 按约定口径提供队列、调用、失败、来源失效和清理指标；避免重复统计数据库全局 Gauge，不将面单正文、凭证或高基数私有编号作为标签。

### IMG-13：尚无独立解除某个事项图片关系的完整入口（P2）

- **现状与依据：** 现有来源纠错可以使关联决定或消息失效，全局撤回会失效所有图片关系；[task_attachments](../app/media/context.py) 有关系版本，但没有专门的按单一事项解除指定附件关系 API 与界面。
- **验收：** 解除单一关系不撤回其他事项仍有权使用的材料，并与原话纠错、并发执行和确认版本协调；全局撤回继续使所有关系失效。

### IMG-14：观察级使用依赖尚未完全建模（P2）

- **现状与依据：** [dependency_stamp](../app/media/context.py) 和 [ProvenanceGuard](../app/tasks/provenance.py) 已跟踪资产状态/代数、有效期、事项关系版本与来源修订，工具及关联证据也保存观察编号；但没有把每次已展示观察的完整有效状态统一纳入该依赖戳。当前主要失效通过撤回和来源修订实现，独立观察替代尚未形成全链路。
- **验收：** 观察单独失效或被替代时，已用它的模型上下文、后续工具、回复和确认均能重新校验；追加无关观察不无故废弃其他有效观察，晚到旧结果不复活失效依赖。

## 评测与运行扩展

### EVAL-01：正式场景库与外部数据适配未完成（P2）

- **保留设计：** [Agent评测设计](Agent评测设计.md)、[RAG评测说明](RAG评测说明.md) 和 [开源评测数据集](开源评测数据集.md) 的业务场景覆盖。
- **现状与依据：** [静态/动态 Agent 示例](../app/evaluation/agent)、[RAG 示例](../app/evaluation/rag/datasets) 可运行，动态模拟和记忆配对已经实现；示例不是正式校准题集，外部数据没有自动转换为当前 schema 的导入器。
- **验收：** 固定来源与版本，补充真实对象映射、人工标注、数据划分及关键失败场景。派生评测与上游排行榜分别报告，不把模板例题通过率当作业务质量成绩。

### EVAL-02：模拟器、裁判和记忆使用质量仍需校准（P2）

- **保留设计：** Agent 文档中的稳定模拟、业务裁判及记忆使用/重复询问评价。
- **现状与依据：** [simulator.py](../app/evaluation/agent/simulator.py)、[judge.py](../app/evaluation/agent/judge.py) 已有行为复核与证据引用校验；[reporting.py](../app/evaluation/agent/reporting.py) 对没有可靠判据的使用质量、错误使用与重复询问保持空值，不输出伪分数。RAG 裁判也需要人工语义抽检。
- **验收：** 建立正反与边界校准样本，区分模拟错误、产品错误和未评分；新增记忆指标具有独立标注和实际来源，保留覆盖率与未评分数。

### EVAL-03：多会话实验尚不支持业务时间跳跃（P3）

- **保留设计：** Agent 文档的多会话计划包含时间推进、偏好变化及状态演进。
- **现状与依据：** [SessionPlan](../app/evaluation/agent/contracts.py) 无时间推进字段，[simulation.py](../app/evaluation/agent/simulation.py) 支持多个新会话但没有可控业务时钟；不能靠修改文字日期模拟真实有效期变化。
- **验收：** 为业务、政策和记忆有效时间提供一致可控时钟，覆盖报价过期、偏好时间范围和跨天流程，保留事件时间与观察时间。

### EVAL-04：记忆对照未覆盖全部部署条件（P2）

- **保留设计：** Agent 文档中的多会话记忆生命周期与效果对照。
- **现状与依据：** [memory.py](../app/evaluation/agent/memory.py) 和 [sandbox.py](../app/evaluation/agent/sandbox.py) 用隔离环境运行真实 v3 提取/提交，在会话结束设归档屏障；关闭向量与外部缓存，不模拟会话内异步提取竞争。当前结果不能代表部署中的向量召回和并发行为。
- **验收：** 按需增加独立的向量、缓存及异步竞争实验，仍保留同快照分支与来源记录，不能把等待归档成功视为异步路径已验证。

### EVAL-05：没有原始对话历史导入后仅评末轮的入口（P3）

- **保留设计：** Agent 文档中固定完整上下文、仅生成末轮答案的阶段评测用途。
- **现状与依据：** [静态运行器](../app/evaluation/agent/runtime.py) 重新执行 `steps`，不原样装入既有双方历史；动态运行器生成新的用户轨迹。
- **验收：** 若增加该模式，明确历史是否为公开已发生事件、来源与事项初态、末轮生成边界及评分范围，不能混报为重跑全部用户步骤的结果。

### INF-01：业务库事务 Outbox 与消息总线仍为保留方向（P3）

- **保留设计出处：** [系统架构设计](系统架构设计.md) 明确列出的 MySQL 交易 Outbox / RocketMQ 尚未接入方向。
- **现状与依据：** [runtime/outbox.py](../app/runtime/outbox.py) 是支持库任务机制；[runtime/notifications.py](../app/runtime/notifications.py) 是持久通知；MySQL 有 `business_operation_receipts` 和 `commerce_provider_requests`，但没有对应的通用交易 Outbox 发布/消费实现或 RocketMQ 依赖。
- **验收：** 只有需要跨服务事件投递时再落实该方向，保证业务变更与发送意图同事务、投递至少一次、消费幂等及回执恢复；不将现有支持库 Outbox 描述为已经接入消息总线。
