# 多轮任务代码自审与验收

日期：2026-10-13。范围：`codex/multiturn-tasks` 相对人工接管基线 `a3c2936` 的新增实现。本次为实现后的代码自审，不是独立审核。

## 已修复的发现

| 发现 | 修复与验证 |
| --- | --- |
| LLM 观测包装丢弃 `tool_calls`，真实执行器无法调用提问或业务工具 | 保留工具调用 choices；API 测试贯通实际包装、ReAct、提问、补充、确认和模拟退款 |
| 任务创建时间可能相同，多诉求展示与执行顺序不稳定 | 使用事务内会话事件序号保存创建顺序 |
| 取消排队中的待办可能中断正在处理的其他任务 | 后台取消只更新目标任务，不增加当前执行版本；测试验证原 Worker 仍能发布 |
| 补充原因包含“快递”等关键词可能错误创建新诉求 | 缺少明确新请求表达时优先回答当前问题，保持任务 ID |
| 多笔同类待办导致取消目标不明确；回答选择后可能丢失改口的新诉求 | 保存原始指令；选定目标后恢复取消/暂停/改口及后续新诉求 |
| 旧订单和其他待办上下文可能污染新执行参数 | 每任务筛选消息上下文，重建补充字段时替换旧订单，重新查询业务依据 |
| 迟到响应可能清除新输入或展示过期确认 | 前端请求序号与服务端控制版本双重检查，后台发布继续校验控制版本 |
| 模型可能生成未经查询的订单选项 | 只保留本轮成功查询支持的订单选项，测试过滤虚构订单号 |
| 在途业务写操作不能被任务取消真正撤回 | 保留执行结果并转人工核实；已成功提交不标记为“取消成功” |

## 验证结果

- 后端全量回归：424 通过，2 项未运行。两项既有 Redis 集成测试固定连接本地端口并使用 `FLUSHDB`，本次未执行。
- 测试运行时显式清空订单 DSN、订单缓存 Redis、Memory Redis 和并发 Redis 配置，使用 JSON 会话/记忆、关闭意图模型和审计外连；新增测试用临时 SQLite、模拟模型与模拟订单工具。没有访问真实订单数据库或提交真实退款。
- 前端：`npm run build` 通过。
- Edge 无头浏览器：三个待办共存、刷新恢复问题、选择订单后继续退款、独立确认、暂停/恢复、切换到物流、取消退款保留其他待办、文字改口均通过。检查 390px 手机宽度无横向溢出，无 JavaScript 页面异常。
- 并发/安全回归：同时回答同一问题只接受一份；旧问题和跨会话任务被拒绝；取消后旧回复/工具被拦截；幂等重试不重复创建任务；人工接管冻结任务；历史工单只展示结束前的任务快照。
