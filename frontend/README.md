# 前端维护约定

前端使用 React、Vite 和普通 CSS。重构保持已有页面与接口协议，不引入路由、全局状态库或通用组件框架。

## 目录职责

- `App.jsx`：登录状态与客户/人工工作台入口。
- `CustomerWorkspace.jsx`：客户侧导航。聊天组件切换页面时保持挂载，保留草稿和消息订阅。
- `auth/`：登录与注册。
- `commerce/`：订单、优惠券、筛选标签与数据请求；`CustomerProfile.jsx` 展示账号及会员资料。
- `chat/`：会话订阅、发送与重试、业务操作状态、消息气泡。`TaskConversation.jsx` 只负责组装界面。
- `support/`：人工工单详情、权限设置、操作核实。`SupportConsole.jsx` 负责工单列表。
- `api/client.js`：统一请求入口，负责 Cookie、CSRF 和接口错误。
- `shared/format.js`：金额和日期格式化；`chatTime.js` 负责聊天时间分组。
- `conversationState.js`：纯状态函数，负责消息去重、游标、待发送恢复及回复覆盖判断。
- `styles.css`：样式导入入口。`styles/` 按基础、登录、会话/人工工作台和客户页面划分。

## 代码与样式

1. 组件负责展示和交互；复杂订阅与异步状态放在对应功能的 Hook。只有实际复用的逻辑才提取到共享模块。
2. 使用 Prettier 统一格式，避免单行堆叠 JSX、重复格式化函数和大组件内嵌多个独立页面。
3. 修改样式时定位现有规则；不要在文件末尾不断追加同名选择器。客户界面覆盖规则用 `.customer-shell` 或 `.customer-workspace` 限定范围，避免影响人工工作台。
4. 保留现有字号、间距、响应式布局、焦点样式和减少动画偏好。优惠券卡片样式是用户确认的设计，修改须有明确需求。
5. 日期没有时区后缀时按服务端 UTC 解释；展示用浏览器本地时间。缺失或无效值使用明确占位文案。
6. 依赖使用确定版本并提交 `package-lock.json`；安装使用 `npm ci`。升级依赖后运行完整检查。

## 异步与业务约束

- 读取请求在卸载或切换上下文时取消；迟到响应不得写入其他页面或会话。分页失败保留已加载内容，允许重试。
- 发送失败不代表服务端未接收。重试必须复用原 `request_id`，刷新后恢复待核实消息。SSE 的接收确认优先于迟到的 HTTP 失败。
- 发消息、HTTP 回执、SSE 回复的到达顺序不能假定固定。输入提示按回复覆盖的 `received_sequence` 判断，旧回复不能清除后续问题的等待状态。
- 智能客服回复超时由 `chat/useReplyTimeout.js` 管理：最后一次发送后 60 秒无对应回复，显示优优的超时提示并停止输入动画；继续发送重新计时，迟到的真实回复正常接收。提示仅用于页面反馈，不写入服务端会话或取消后台业务操作。
- 新会话要清理当前 UI 状态，旧会话响应不得清空新草稿或显示旧错误；切换导航不会创建新会话。
- 业务操作确认使用服务端 token、版本和权限状态。相同操作不可并发提交；轮询快照不能覆盖正在进行的操作。结果不明时只核实原操作，不能创建重复操作。
- 客户消息与人工内部备注保持各自展示规则，SSE 权限撤回后停止订阅并清空会话数据。
- Enter 发送，Shift+Enter 换行；输入法候选确认和长按重复按键不能触发发送。

## 验证命令

```sh
npm ci
npm run dev
npm run format
npm run check
```

`check` 依次运行格式检查、纯函数测试、生产构建和浏览器测试。浏览器测试使用模拟 API 与独立的 5178 端口，不向真实客服会话发消息。Windows 默认使用 Edge；其他平台需安装 Playwright 浏览器，也可以通过 `PLAYWRIGHT_CHANNEL` 指定已安装的浏览器。

浏览器回归覆盖客户导航、筛选与分页、个人信息、移动端布局、会话重试/重放、输入提示、时间分组、业务确认与人工交接。新增测试应针对用户行为、异步顺序或业务约束，不要只重复组件实现。

后端地址可用 `VITE_API_BASE_URL` 配置，默认 `http://localhost:8010`。
